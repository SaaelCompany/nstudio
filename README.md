# NStudio

Ядро для программ и игр, которые собираются из нод. Сейчас это исполнитель графа, реестр плагинов и редактор. Сцен, спрайтов и физики здесь нет: их позже добавляют плагины, не меняя ядро.

## Запуск

```bash
npm install
npm run dev
```

Проверки: `npm test`. Сборка: `npm run build`.

В редакторе уже открыт пример: «Старт» печатает приветствие и сумму 2 + 40. Кнопка **Запуск** выполняет событие `start`. Проект сохраняется в браузере и в файл `*.nstudio.json`.

## Как устроен граф

У ноды одна из четырёх ролей:

- **event** — вход в программу. Ядро знает событие `start`. Хост или плагин может послать своё, например `tick`.
- **exec** — выполняется, когда на вход приходит поток, и сама зажигает выходы потока.
- **pure** — без потока. Результат вычисляется в момент, когда следующая нода читает выход.
- **inert** — только свойства на холсте. Исполнитель такие ноды пропускает.

Провода потока задают порядок. На вход потока можно подать несколько проводов: нода сработает на каждый. Провода данных читаются, когда нода спрашивает вход, и у такого входа провод один. Выход можно раздать нескольким нодам. Цикл по данным — ошибка. Цикл по потоку останавливается лимитом шагов, программа не зависает.

Документ — это JSON версии 1: ноды, связи, переменные и поле `extensions`. В `extensions` плагин хранит свои данные проекта, ядро их не разбирает. Неизвестный тип ноды не выбрасывается: проект открывается, а проверка просит подключить плагин.

## Плагины

Плагин — обычный TypeScript-модуль. Файл проекта код не исполняет.

```ts
import { definePlugin, Engine, stringValue } from './core'

export const notes = definePlugin({
  id: 'example.notes',
  name: 'Заметки',
  version: '0.1.0',
  register(api) {
    api.registerCategory({ id: 'examples', label: 'Примеры', color: '#7f8c99' })
    api.registerNodeType({
      id: 'example.note',
      title: 'Заметка',
      category: 'examples',
      description: 'Текст на графе.',
      role: 'inert',
      inputs: [],
      outputs: [],
      properties: [
        { id: 'text', label: 'Текст', dataType: 'string', defaultValue: stringValue('Заметка'), widget: 'text' },
      ],
    })
  },
})

const engine = new Engine()
engine.use(notes)
```

Регистрация идёт в таком порядке: категории, типы данных, ноды. Если `register` бросает ошибку, ядро откатывает всё, что плагин успел добавить. Повторно тот же `id` подключить нельзя.

Чистая нода не должна ничего менять: исполнитель может вызвать `compute` несколько раз. Событийная нода с методом `execute` сама решает, когда звать `trigger`. Поле `payload` приходит от хоста, например `{ dt: 0.016 }` для будущего кадра игры.

В редакторе кнопка «Подключить пример плагина» регистрирует `src/example-plugin.ts` и сразу показывает ноду «Заметка».

## Встроенные ноды

События: Старт. Поток: последовательность, ветвление, повтор. Данные: число, строка, логическое, склейка текста. Математика: сложение, вычитание, умножение, деление, остаток, сравнение. Логика: и, или, не. Переменные: прочитать и записать. Отладка: печать в консоль запуска.

## Что остаётся плагинам

Объекты сцены, спрайты, ввод, физика, звук и игровой цикл сюда не входят. Плагин регистрирует свои ноды и типы, а хост вызывает `engine.run(document, { event, payload })`.
